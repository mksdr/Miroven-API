# Reporting a vulnerability

[English](#english) · [한국어](#한국어)

## English

Report API vulnerabilities through the Miroven project's [private GitHub reporting page](https://github.com/mksdr/Miroven/security/advisories/new). Identify **Miroven-API** and include the affected version/commit, deployment mode, synthetic reproduction steps, and security impact. Do not post exploit details in public issues or pull requests before coordinating with the maintainer.

Do not send real journals/photos, email codes, recovery codes, keys, credentials, cookies, deletion receipts, or unredacted database backups/logs. If private reporting is unavailable, request a private channel from the maintainer without publishing exploit details. See [authentication and security](https://github.com/mksdr/Miroven/wiki/API-Authentication) and [validation boundaries](https://github.com/mksdr/Miroven/wiki/API-Validation).

## 한국어

API 취약점은 Miroven 프로젝트의 [GitHub 비공개 신고](https://github.com/mksdr/Miroven/security/advisories/new)를 이용하세요. **Miroven-API** 문제임을 표시하고 버전/커밋, 배포 방식, 합성 데이터 재현 순서와 보안 영향을 설명하세요. 관리자와 조율하기 전에 공개 이슈나 PR에 악용 방법을 게시하지 마세요.

실제 기록·사진·이메일 코드·복구 코드·키·인증정보·쿠키·삭제 영수증·미정리 DB 백업/로그는 보내지 마세요. 비공개 신고 기능을 사용할 수 없다면 악용 방법을 공개하지 말고 관리자에게 비공개 연락 경로를 요청하세요. [인증·보안](https://github.com/mksdr/Miroven/wiki/API-Authentication.ko)과 [검증 범위](https://github.com/mksdr/Miroven/wiki/API-Validation.ko)를 참고하세요.
